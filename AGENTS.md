# vibeblog

npm-workspaces monorepo for `@vibelabsdotto/blog`, a drop-in MDX blog for Next.js App Router sites.

- `packages/blog` is the published package. Source in `src/`, built with tsdown to `dist/`. The CLI is `bin/vibeblog.mjs` (plain Node, no build step).
- `apps/example` is a demo site that consumes the package through the workspace link. Its `app/blog/*` and `lib/blog.ts` were generated by `npx vibeblog init`.

## Commands

- `npm run dev` builds the package once, then starts the example on port 3077. Rebuild the package with `npm run build:package` (or keep `npm run dev:package` running) after editing `packages/blog/src`.
- `npm run build` builds the package and the example in production mode.
- `npm run typecheck` checks the package.

## Rules

- Keep bare `next/link` and `next/navigation` imports. Next aliases them per layer; `next/link.js` breaks route handlers at build time.
- Read post files with sync `fs`. Next treats it as a predictable value while prerendering, which keeps `cacheComponents` sites working.
- The stylesheet stays plain CSS on `.vb-*` classes and reads shadcn variables. Don't add Tailwind classes to package components; host sites don't scan `node_modules`.
- Before publishing, run `npm pack --dry-run` in `packages/blog` and check the file list (dist, bin, README, LICENSE).
